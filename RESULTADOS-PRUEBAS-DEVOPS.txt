PRUEBA 6 — GitHub Actions real: workflow "dora-metrics" (tracking DORA)
------------------------------------------------------------------------
Cómo se hizo:
  6.1) Verificación del trigger workflow_run: se revisó si
       dora-metrics.yml se disparaba junto con el CI del PR (todavía
       en la rama devops/dora-metrics, no en main).
  6.2) Tras mergear el PR a main, se volvió a verificar si el mismo
       trigger se activaba con el run de CI sobre main.
  6.3) Se creó y subió un tag real de release para probar el
       registro de despliegue:
         git tag v0.1.0 && git push origin v0.1.0
  6.4) Se corrió npm run dora:report localmente, después de traer
       (git pull) los datos que los workflows habían commiteado solos
       en main.

Resultado:
  6.1) ⏸️ Con el PR sin mergear, dora-metrics.yml NO se disparó. Causa
       real identificada: GitHub Actions solo activa el trigger
       "workflow_run" para workflows que ya existen en la rama
       default del repo (main); como el archivo vivía solo en la rama
       del PR, GitHub todavía no lo tenía registrado como oyente. No
       es un bug del pipeline, es un comportamiento documentado de
       GitHub Actions.

  6.2) ✅ Después de mergear, el mismo evento SÍ disparó dora-metrics.yml:
       https://github.com/KeystrokeVision/kryptos/actions/runs/31567904471
       ✅ SUCCESS — job "record-build-result" corrió (antes salía
       "skipped") y commiteó un evento real:

          "timestamp":"2026-08-12T05:51:05.024Z"}

  6.3) ✅ El tag v0.1.0 disparó dora-metrics.yml por el evento
       "push tags":

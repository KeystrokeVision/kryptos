1. OBJETIVO
------------------------------------------------------------------------
Implementar en Kryptos las 4 métricas DORA (DevOps Research and
Assessment) —el estándar de la industria para medir velocidad y
estabilidad del ciclo de entrega de software— usando las herramientas
descritas en la tabla de referencia:

  Herramienta              | Métricas que debía cubrir
  --------------------------|-------------------------------------------
  GitLab / GitHub Actions   | Deployment Frequency, Lead Time, MTTR,
                             | Change Failure Rate (DORA completas)
  Azure DevOps              | Tiempo de despliegue, frecuencia de
                             | liberación, tasa de fallos en builds
  Jenkins / CircleCI        | Build Success Rate, duración de
                             | pipelines, análisis de fallos en CI
  Harness                   | Deployment Frequency, automatización de
                             | rollbacks, análisis de impacto

------------------------------------------------------------------------
2. QUÉ SE IMPLEMENTÓ (archivos en el repo)
------------------------------------------------------------------------

  .github/workflows/ci.yml            -> Build + typecheck en cada
                                          push/PR a main
  .github/workflows/dora-metrics.yml  -> Registra despliegues (tags
                                          vX.Y.Z) y resultados de build
                                          en main -> las 4 métricas DORA
  azure-pipelines.yml                 -> Plantilla Azure DevOps
  Jenkinsfile                         -> Plantilla Jenkins
  .circleci/config.yml                -> Plantilla CircleCI
  .harness/kryptos-pipeline.yaml      -> Plantilla Harness (rollback +
                                          análisis de impacto)
  scripts/dora-metrics.mjs            -> Motor de cálculo compartido
                                          (record-deploy, record-build,
                                          report), sin dependencias
  metrics/deployments.jsonl           -> Histórico de despliegues
  metrics/failures.jsonl              -> Histórico de builds (éxito/
                                          falla) en main
  metrics/README.md                   -> Esquema de datos
  DEVOPS.md                           -> Resumen de las 5 plataformas
  package.json                        -> Nuevo script "dora:report"

Las 5 plataformas comparten el mismo motor de métricas
(scripts/dora-metrics.mjs) para que los números sean comparables sin
importar cuál se use.

6. HALLAZGO IMPORTANTE — por qué dora-metrics.yml NO se disparó todavía
------------------------------------------------------------------------
Se verificó también si .github/workflows/dora-metrics.yml (el que
registra Change Failure Rate/MTTR vía el evento "workflow_run") se
activó junto con el run de CI. RESULTADO: no se disparó — GitHub
Actions solo escucha el evento "workflow_run" para workflows que ya
existen en la rama por defecto del repo (main). Como dora-metrics.yml
todavía vive solo en la rama devops/dora-metrics (no fue mergeado a
main), GitHub todavía no lo registra como "oyente" de ese evento.

Esto es una limitación conocida y documentada de GitHub Actions, no un
error del pipeline. Se soluciona solo con mergear el PR #1 a main: a
partir de ahí, cada vez que "CI" corra sobre main, dora-metrics.yml se
va a disparar automáticamente y va a empezar a poblar Change Failure
Rate y MTTR con datos reales.
